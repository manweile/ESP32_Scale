Here is a concrete refactoring example (diff) based on your actual project structure for moving all calibration user input handling to `handleCalibrationInput`. This refactor assumes your main Arduino loop is in **PropaneScale/PropaneScale.ino** and it already calls `tickCalibration()` (or will after this change):

---

### 1. **Remove Serial Input Handling from `tickCalibration`**

**Before:** (in `PropaneScale/src/workflows/calibration_workflow.cpp`)
```cpp
if (calCtx.state == CalState::WAIT_EMPTY) {
    if (Serial.available()) {
        char c = Serial.read();
        // User input handling for 'q', 'z'...
    }
    // ...timeout logic
}
```

**After:**  
```cpp
if (calCtx.state == CalState::WAIT_EMPTY) {
    // Only handle timeout logic here.
    // User input is now handled in handleCalibrationInput() by the main loop.
    // ...timeout logic
}
```

> Remove the entire `Serial.available()` block and all user input checking from **tickCalibration**.

---

### 2. **Update Main loop() in PropaneScale.ino**

#### Find your current main loop (example context from results):

```cpp
void loop() {
    // ...other variable declarations...
    // Main loop body...
}
```

**Insert this code before calling tickCalibration():**
```cpp
    // If calibration is active and a serial character is available, route it to handleCalibrationInput
    if (calCtx.state != CalState::IDLE && Serial.available()) {
        char c = Serial.read();
        handleCalibrationInput(c);
    }

    tickCalibration();
```

**Full Example Integration:**
```cpp
void loop() {
    // ...other variables, logic...

    if (calCtx.state != CalState::IDLE && Serial.available()) {
        char c = Serial.read();
        handleCalibrationInput(c);
    }

    tickCalibration();

    // ...rest of your loop logic, if any

```

- User input is now directed exclusively through `handleCalibrationInput()`.
- `tickCalibration()` only advances state based on timing and sensor logic.

### 4. **Sanity Check handleCalibrationInput**

No changes are necessary if `handleCalibrationInput(char)` already handles all relevant states/inputs (WAIT_EMPTY, ADJUSTING, etc.).  
If not, move the user-input logic that was previously in `tickCalibration` into the corresponding `handleCalibrationInput` state branch.

---

## Summary of Improved Flow

- **loop()**:
    - Reads and routes input to `handleCalibrationInput()` if calibration is active.
    - Always calls `tickCalibration()` to advance the non-blocking state machine.

- **handleCalibrationInput()**:
    - Handles ALL user calibration input logic per-state.

- **tickCalibration()**:
    - Handles timeouts, sensor readings, and ordinary state transitions only.

---

## Resulting Advantages

- **Single responsibility**: All calibration input logic in one place.
- **Non-blocking**: `loop()` stays responsive.
- **Easy to maintain** and reason about calibration workflow logic.
