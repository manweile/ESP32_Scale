Non-blocking HX711 sampler proposal

Goal
- Replace runtime blocking HX711 calls (e.g., `wait_ready_timeout()`) with a small non-blocking sampler to avoid stalling the main loop and to keep Web BLE / WiFi responsive in production.
- Provide simple API: `startSample()` to begin an asynchronous batch and `pollSample()` to advance/complete it (one call per loop tick).

Design constraints and assumptions
- Production: Serial monitor I/O will not be used concurrently with BLE/WiFi — only during development. 
  Production must avoid blocking HX711 calls.
- The sampler must NOT call or depend on the HX711 library's potentially-blocking low-level helpers such as `read()`, `get_offset()`, or `get_scale()`; 
  these are explicitly excluded from runtime use in production paths. 
  The higher-level `get_units()` function is acceptable to call in runtime.
- Instead, the sampler should obtain raw ADC counts via a non-blocking, single-sample mechanism implemented either:
  - in a small, non-blocking extension to the HX711 library (recommended) that exposes a single-sample API (e.g. `beginRawRead()` / `completeRawRead()` or `readRawNonBlocking()`), or
  - by implementing a minimal, careful GPIO-driven pulse reader inside `scale_io` that performs one raw sample read when data is ready (avoid loops and blocking delays).
- The sampler must perform at most one raw read per invocation of `pollSample()` (i.e., one read per loop tick when data is ready), avoiding long blocking loops.
- Provide optional timeout/cancel semantics so callers can recover from stuck or unresponsive sensors without blocking.

API (proposed)
- bool startSample(int requestedReadings, int samplesPerReading, unsigned long timeoutMs = 0)
  - Starts an asynchronous sampling batch that will collect `requestedReadings` averaged readings, where each averaged reading is the mean of `samplesPerReading` raw samples.
  - Returns `true` if the sampler was started; `false` if a batch is already in-progress.
  - `timeoutMs == 0` means no timeout.

- bool pollSample(float &outAvg)
  - Called once per main-loop tick (or from workflow tick functions). Returns `true` when the entire batch is complete and writes the final averaged units into `outAvg`.
  - Returns `false` if the batch is still in progress or if no batch is active.
  - If the batch times out, the function should return `false` and mark the batch inactive; callers can detect timeout via an optional error reporting accessor (see below).

- Optional helpers (recommended):
  - bool isSampleActive()
  - void cancelSample()
  - int sampleProgress() -> number of completed readings / requestedReadings
  - int sampleSubProgress() -> number of collected samples in current reading / samplesPerReading

Internal state (in `src/scale_io.cpp`)
- struct SampleCtx { bool active; int requestedReadings; int samplesPerReading; int currentReadingIndex; int currentSampleIndex; double readingAccum; double totalAccum; unsigned long startMs; unsigned long timeoutMs; bool timedOut; } sampleCtx;

pollSample() behavior (detailed)
1. If `sampleCtx.active == false` return false.
2. If `sampleCtx.timeoutMs != 0` and `millis() - sampleCtx.startMs >= timeoutMs`, set `sampleCtx.timedOut = true`, deactivate `sampleCtx.active` and return false.
3. Check sensor readiness with `scale.is_ready()` (fast, non-blocking). If not ready, return false (try again next tick).
4. Obtain a single raw ADC count using a non-blocking raw-read mechanism (one of):
  - call the HX711 non-blocking helper `readRawNonBlocking()` (or `beginRawRead()`/`completeRawRead()` pair) if the HX711 library is extended, or
  - perform a single GPIO-based raw read implemented locally in `scale_io` that carefully samples the HX711 data pin without blocking other tasks.
  The key requirement is a single-sample, non-blocking read per `pollSample()` invocation.
5. Convert raw->units inside `scale_io` using either:
  - a call to `scale.get_units(samplesPerReading)` (acceptable if preferred), or
  - a local conversion using cached offset/scale calibration values (avoid calling `get_offset()`/`get_scale()` each sample).
  The key requirement is to avoid low-level blocking reads — do not call `read()` repeatedly inside tight loops; prefer one-sample-per-tick behavior whether using `get_units()` or a local conversion.
6. Accumulate into `sampleCtx.readingAccum += units; sampleCtx.currentSampleIndex++`.
7. When `currentSampleIndex >= samplesPerReading`: compute readingAvg = readingAccum / samplesPerReading; accumulate `sampleCtx.totalAccum += readingAvg`; increment `currentReadingIndex`; reset `readingAccum` and `currentSampleIndex`.
8. When `currentReadingIndex >= requestedReadings`: compute finalAvg = totalAccum / requestedReadings; deactivate sampleCtx.active; set outAvg = finalAvg; return true.
9. Otherwise return false (still in-progress).

startSample() notes
- Must initialize `sampleCtx` fields and set `active = true`.
- If sampler is active, return false so callers can choose to poll later or cancel the current batch.

Integration details
- Replace runtime calls to `averageUnits()` / direct `get_units()` in workflows with `startSample()` + repeated calls to `pollSample()` inside the existing tick functions. Example:

    // start a batch (only once)
    if (!startSample(CAL_SAMPLES, LIVE_SAMPLES, SAMPLE_TIMEOUT_MS)) {
      // sampler busy or failed to start
    }

    // inside tick (called frequently)
    float result;
    if (pollSample(result)) {
      // result is final averaged units
      // use as before
    } else {
      // still collecting; return to main loop quickly
    }

- For callers that previously relied on `averageUnits()` semantics (which used `get_units(samplesPerReading)`), implement a small adapter that maps the old state machine to the new one (use `sampleCtx` or reuse `avgCtx` fields for minimal edits).

Error handling and diagnostics
- If `pollSample()` times out, record a diagnostic string and optionally call `printDiagnostic()` in non-production builds (or when a debug flag is enabled). Production code should handle timeout gracefully (e.g., cancel workflow, report failure to UI).
- Keep `ensureScaleReady()` limited to setup and diagnostics: it may still call `wait_ready_timeout()` for user-visible checks, but avoid calling it in runtime flows.

Performance considerations
- One non-blocking raw read per `pollSample()` call keeps each tick short; at typical HX711 rates this yields naturally paced sampling without blocking BLE/WiFi.
- If the system needs faster sampling than one read per loop tick, allow callers to call `pollSample()` multiple times per loop or implement a `maxReadsPerTick` parameter (use cautiously — don't starve network tasks).

Backward-compatibility & Development notes
- Maintain `averageUnits()` as a shim that uses `startSample()`/`pollSample()` under the hood; 
  this minimizes changes in workflow code. 
  The shim must also avoid calling `get_units()` or other blocked library helpers — use cached calibration parameters and the sampler's local conversion instead.
- Leave Serial-based diagnostic and queued writer logic intact for development, 
  but guard heavy Serial use behind a compile-time flag (e.g., `#ifdef DEV_SERIAL`) so production builds exclude or reduce Serial activity.
